## Relevant documentation

- ARM: `reverse_engineered_functions.md`, “The .arm army-roster file format,” `ReadArmyFileRaw` at `0x00451670`. Only explicitly listed headline record offsets are interpreted. All declared records are bounds checked before decoding.
- SPR: “Sprite format (.SPR),” `LoadSpriteSheet` at `0x004821c0`, and “sprite pixel-decoding pipeline.” Current decoder supports the described uncompressed layout and rejects unsupported variants.
- MAD/SAD: “.MAD/.SAD audio,” `MadDecode` at `0x004aa8f0`, `SadDecode` at `0x004ad990`. Tests cover nibble ordering, independent stereo state and signed PCM escape samples. Direct inspection of `MadAdpcmBlockDecompress` and `SadAdpcmBlockDecompress` in the open `DarkOmen.exe` Ghidra project corrected two omissions in the prose: each block emits the initial predictor frame, and either invalid stereo index switches the decoder into terminal PCM passthrough. The raw tail continues across 1024-byte read-ahead boundaries without new headers. This explains two-byte MAD tails and SAD tails that otherwise look like invalid ADPCM blocks. Regression tests cover both cases. Real-file acceptance does not establish audible fidelity or correct sample rate.
- Combat: “missile/melee combat-resolution engine.” The documentation establishes hit/wound/save stages, but the exact tables are not present in the supplied prose. Ranged units now use ARM missile-weapon presence, provisional weapon-class range, and original BOLT/CANNON sprites for flight; ballistic skill, strength/toughness and low ARM armour bits drive temporary impact resolution. The sandbox's thresholds and speeds are explicit stand-ins, not reconstructed values.
- CTL: “.CTL bytecode VM” documents 240 dispatch entries and confidence levels. Many entries summarize calling behavior rather than giving complete executable semantics. No unsupported opcode is silently treated as a working mission implementation.

## BTB discrepancy

The early prose describes disk chunks 1=header, 2=objectives, 3=obstacles, 4=regions, 5=game objects. The later confidence database instead labels 2=obstacles, 3=game objects, 4=base, 5=regions. The installed B1_01.BTB has a 240-byte type-1 chunk, a 120-byte type-2 chunk, a 1772-byte type-3 chunk, 21 type-4 chunks, and a 3652-byte type-5 chunk. This supports the early structural description but does not by itself establish the engine dispatch semantics. Direct inspection of `Btb_ParseChunks` at `0x00451080` and its callees resolved the conflict: the function named `Btb_ParseRegionChunk` actually populates 24-byte game-object records from type-5 chunks and nested item 503. Its nested fields 1/2 supply X/Z, 5 flags, 12 unit ID and 13 script ID. The function named `Btb_ParseBaseChunk` handles the type-4 named regions. The prior function names and prose summaries were misleading. The new setup reader uses these verified field writes and real-file layouts, while retaining a generic lossless chunk reader. No external Ghidra names or documentation were changed.

## Runtime sources and limits

`executable.cpp` reads file-backed PE32 sections with bounds checks. Campaign opcodes use original handler addresses as identifiers; `campaign_opcodes.inc` records operand widths. Entry point is `0x4c3d68`. Book, map, talking-head and movie adapters resume original control flow. No native executable code is invoked.

`ctl_widths.inc` records the 240 dispatch operand widths, including unused operands. CTL function IDs below the header bias resolve through `table[bias + id]`; shared functions 100+ resolve through `table[id - 99]`. Unknown operations, invalid addresses, stack overflow and exhausted instruction budgets fail explicitly. Some implemented host adapters deliberately simplify search, combat and movement; periodic scheduling and individual-member wandering remain host gaps. Granted ability IDs are retained but spell execution is not implemented.

Sprite registry records begin at `0x4ceb7c` with 44-byte records. Animation lookup follows `FUN_0047fdf0`: the sprite's signed table index at `0x4ebc88` selects pointers in `0x4eb358`. Visual runs use opcode 9's base bank and negative shorts as complemented frame numbers. `FUN_00469e70` emits one such frame per animation tick. The renderer follows the eight-direction frame formula observed in `FUN_0042b6a0`. It extracts initial idle/walk/attack runs; it does not emulate the entire animation VM. World sprite scale is provisional.

Next work: complete remaining CTL operations and their battle-host behaviors; implement original combat/missile/magic tables, pathfinding; expand animation execution to deaths and effects; replace remaining campaign text adapters with original presentation and army management. The route tests simulate mission results and do not imply those missions are fully playable.

## Movie playback and frontend

`movie.cpp` uses libavformat/libavcodec's send/receive decoder API and libswscale/libswresample for RGBA and 44.1 kHz stereo PCM output. Packet/frame lifetimes and SDL audio devices are owned by a scoped movie object. Decoding runs a short interval ahead of the presentation clock, with packet/frame budgets; completion drains codec and resampler output. Closing or skipping a movie clears queued audio and releases its decoder. Startup audio corruption is bounded and logged rather than silently aborting the introduction.

`frontend.cpp` implements the documented English `ENG.TGQ -> INTRO.TGQ -> MainMenu.bmp` sequence, including the first-movie skip branch. Menu registration positions follow the original 640x480 Y coordinates 250, 290, 330, 370, 410 and 450. Letterboxing transforms both drawing and mouse input. `renderer.cpp` decodes original FNT glyph metrics, packed nibbles and palette data for F_MENBG/F_MENBGR, centering labels by their real advances. New/Load dispatch into the existing campaign controller, Options controls audio/replay, and Continue resumes paused gameplay. Unsupported Multiplayer/Tutorial items are disabled. Campaign `Movie:` prompts use the same movie player and resume script execution when playback completes or is skipped.

FFmpeg API references: [send/receive decoding](https://www.ffmpeg.org/doxygen/8.0/group__lavc__encdec.html), [audio resampling](https://www.ffmpeg.org/doxygen/8.0/group__lswr.html). Startup and menu behavior comes from the supplied `reverse_engineered_functions.md` sections on `ProcessGameStateMachineTick` and `UpdateMainMenu`.

Audio integration reads the installation's `Sound/Script/*.FSM` directly: `sample`, `start-pattern`, pattern `sequence` alternatives and `state-table` transitions. Transitions occur at sequence boundaries. The host supplies sDeploy/sNormal/sEnd for BATTLE1 and sNormal for EERIE9 in menus/campaign screens. This is a provisional host policy; sGood/sBad and mission-specific script selection are not yet reproduced. WAV sample rates come from their headers; headerless MAD/SAD use the provisional 22050 Hz default. Decoding and mixing run on the main thread, with approximately 46–70 ms queued audio; large clip loads can still stall rendering. No original audio assets are bundled.

SHD support: direct decompilation of `Terrain_QueryGridCell` (0x0042a710) resolves the previously undocumented blobs. The file has SHAD magic, payload length, width/height, dictionary-block count, tile count, then size-prefixed tile records and detail bytes. Each 8-byte record contains a signed base and a detail offset; each 8x8 cell reconstructs `(base + detailByte * 128) / 1024` in world units. `FUN_0042af30` compares interpolated ray heights against this field, supporting its use as an occluder-height grid rather than a greyscale image. The native renderer uploads R32F heights and performs bounded directional tracing. Its light direction, shadow strength and sampling are approximations, not recovered original lighting parameters. Bounds checks cover both blobs, shared dictionary offsets and partial edge tiles.

Water rendering applies a vertex-shader deformation only to WATR batches, with two world-space sinusoidal waves (amplitudes 0.12 and 0.06 world units), analytic slope normals and UV flow. Static terrain/furniture and UI draws explicitly disable the water shader branch. Mesh groups remain simultaneous spatial patches: B1_01 groups have different vertex/face counts and tile-like names, so treating them as interchangeable frames would discard parts of the river. Animation time is bounded per frame, reset on map load and frozen by pause. This supplies native vertex animation without claiming recovery of the original wave algorithm.

Mission speech: CTL 0xAE/0xAF now implement `CtlOp_PlaySelf` (0x0047ad30) and `CtlOp_PlayOther` (0x0047ad60), queuing unit index and clip ID. The latter resolves the original regiment ID and sets the condition flag. 0xEA tests pending or active dialogue. `FUN_0047c000` established the 16-request queue and near-duplicate suppression; `FUN_0047c0a0` supplies the speech tables at 0x004e7650 (scripted lines) and 0x004e8008 (generic voice groups). Head IDs come from the existing 44-byte executable registry. Native UI adapters resolve MAD files and render existing HEADS.DB models with audio-driven jaw movement. Exact voice-group policy, random variants, request expiry and SEQ/KEY animation remain incomplete. The deployment tray is rendered and hit-tested only in Deployment phase.
